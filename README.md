# OR-problems-within-IPC-Benchmarks

 The goal of this repository is to detect OR (operations research) subproblems within the IPC domains (precisely the years 2000-2008 for now),
 and to solve the domain's problems with a divide and conquer approach. 

 The solver used in this project is FD (Fast downward)
> FD should be installed locally on your machine

 ---

 ## Prerequisites :
 
 To run the solver and validator, ensure you have the following installed and configured:
* **Python 3**
* **Fast Downward** (The path must be configured in `Solver.py`)
* **Planutils / VAL** (For plan validation)

## Solver Usage :

#### Required Arguments :

*   **domain** : The IPC benchmark domain. (original domain MUST be in **/original_pbs**)
*   **problem** : The specific problem ID (e.g., 18, 04 , each domain has a different amount of problems).
*   **FDparameter** : Choices: lama-first, seq-opt-lmcut.

#### Optional Flags :

*   **- -c** : Triggers the comparison mode. When this flag is passed, the script will automatically run the problem against the standard Fast Downward solver (10-minute timeout limit) and export JSON files containing the metrics for both approaches into the results/ directory.

### Execution example :
```bash
python3 src/Solver.py --c Depots 18 lama-first
```

## How to generate comparison graphs :

Once you have gathered JSON metrics using the --c flag in the solver, you can generate standard IPC comparison 
graphs using the visualization script.

#### Options:

*  **- -comp** : Generates a logarithmic line graph comparing Execution Time vs. Problem Size.

*  **- -len** : Generates a bar chart comparing Plan Length vs. Problem Size.

*  **- -score** : Generates a bar chart comparing standard IPC Scores (Agile & Cost).

```bash
python3 src/compare.py [options] <json1> <json2>

# execution example:
python3 src/compare.py --comp results/Script_Depots_lama-first.json results/FD_Depots_lama-first.json
```

## Plan Validation :

To mathematically verify that the generated plans correctly transition the initial state to the goal state, use the VAL tool provided by planutils.

```bash
#command to activate, replace "planning_env" by your own planning env directory
source ~/planning_env/bin/activate
source ~/planning_env/bin/planutils_activate

val Validate original_pbs/<DOMAIN>/domain.pddl original_pbs/<DOMAIN>/<PROBLEM>.pddl results/plans/<PLAN>.txt
```

Plans are automatically validated when **batch testing** (see bash scripts under the tests directory)
